AI ODD Observer for Quadruped Robots

Capstone project for Kaggle’s Agents Intensive: a multi-agent system that reads ROS2 logs from a Unitree Go2, reconstructs its Current Operating Domain (COD), and determines whether it stayed inside its Operational Design Domain (ODD).

1. Problem & Objectives

The goal is to answer a simple but safety‑critical question: “Did the robot operate within its ODD for this run?” We take raw sensor logs (camera, LiDAR‑derived BEV, IMU) and an ODD definition, then:

  • Extract per‑window ODD‑aligned measurements for perception, motion, and collision risk.
  • Aggregate them into a COD region and compare against the ODD spec.
  • Produce an explainable compliance verdict plus a human‑readable report.

2. Agent System Overview

We use Google ADK + Gemini 2.5 Pro to orchestrate six agents:

  • ODD Spec Agent – parses the natural‑language ODD into axes and limits.
  • Perception Agent – reads camera + BEV and estimates lighting, terrain, obstacle density, stairs, humans, and data source (sim/real).
  • Motion Agent – uses IMU + camera to classify motion state and quantify dynamic limits (accel, jerk, angular velocity).
  • Collision Agent – fuses IMU spikes, BEV obstacles, and camera evidence to detect collisions or near‑misses.
  • Evaluator Agent – constructs the COD region and checks COD ⊆ ODD.
  • Report Agent – synthesizes a narrative report and saves it as an artifact.

All data loading, metric computation, and vision calls are implemented as ADK FunctionTools with explicit prompts. Agent instructions focus on tool sequencing and aggregating outputs.

3. Data & Scenarios (overview)

Sim Real

We evaluate on both simulated and real Go2 runs, windowed into short time slices:

  • Simulation: curated scenarios (e.g., indoor residential, deliberate collisions) with known expected behavior.
  • Real: bagfile‑derived runs with compression artifacts, lighting changes, and real terrain irregularities.

Each window bundles synchronized camera frames, BEV images, and IMU signals, giving all loop agents an aligned view of the robot’s state.

4. Implementation & Reproducibility

Key commands (run from the repo root):

  • python scripts/run_odd_analysis.py – interactive single‑scenario run.
  • python scripts/run_odd_batch_analysis.py – batch runs over multiple scenarios.
  • pytest tests/test_adk_evaluation.py -q – rubric‑based agent evaluation.

Detailed write‑up and design notes live in docs/guides/KAGGLE_CAPSTONE_REPORT.md and related docs under docs/.
