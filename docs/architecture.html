Agent Architecture

The ODD Observer pipeline is implemented as a set of Google ADK agents, each responsible for a specific stage of the analysis. All data access and computation is done via FunctionTools, keeping the agent logic focused on sequencing and aggregation.

📌 Versioning for agents, tools, knowledge, and data is documented in Versioning.

0. High-Level Flow

Data flows through the following agents for a single scenario:

ODD Spec
Perception
Motion
Collision
Evaluator
Report

1. Agent Matrix

Agent Role Inputs Outputs Key Tools
ODD Spec Agent v13.0.0 Parse natural‑language ODD into structured axes and limits. NL ODD description. ODD spec JSON (environment, actors, ego axes). FunctionTools for text → JSON extraction, schema validation.
Perception Agent v14.0.0 Estimate environment‑related ODD axes per window. Camera + BEV images, ODD spec. Per‑window odd_measurements (lighting, terrain, obstacles, stairs, humans) + data_source metadata. list_windows_tool, analyze_window_perception_tool, save_perception_output_tool.
Motion Agent v12.0.0 Quantify ego motion and stability from IMU + camera. IMU traces, camera, ODD spec. Per‑window motion odd_measurements (accel, jerk, roll/pitch, etc.) + motion_state and insights. list_windows_tool, analyze_motion_tool, save_motion_output_tool.
Collision Agent v13.0.0 Detect collisions / near‑misses using IMU + BEV + camera. IMU, BEV channels, camera, ODD spec. Per‑window collision_detected (0/1), min_proximity_m, explanation, key_insights. list_windows_tool, analyze_collision_tool, save_collision_output_tool.
Evaluator Agent v9.0.0 Construct COD region and perform COD ⊆ ODD check. ODD spec + per‑window outputs from loop agents. COD region description, compliance verdict, axis‑level reasoning. FunctionTools to load saved artifacts, aggregate metrics, and build COD.
Report Agent v15.0.0 Produce the final human‑readable compliance report. Evaluator output + summarized loop‑agent insights. JSON report with compliance, executive summary, key findings, issues, recommendations. generate_report_tool (writes odd_compliance_report.json as an artifact).

2. Data Flow Summary

  1. ODD Spec Agent parses the ODD description → ODD spec JSON.
  2. Perception/Motion/Collision agents:
    • Enumerate windows via a shared list‑windows tool.
    • Run their analysis tool per window (FunctionTools with Gemini Vision + metrics).
    • Persist per‑domain outputs through save_*_output tools as artifacts.
  3. Evaluator loads these artifacts, constructs the COD region, and evaluates COD vs ODD.
  4. Report Agent consumes Evaluator + summary state to generate the final report artifact.
