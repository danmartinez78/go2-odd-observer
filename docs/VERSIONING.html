Versioning Guide

How we track versions across agents, prompts, knowledge, data, and reports.

What We Version

  • Agents & prompts: Semantic versions (badges on the site). Source: odd_agents/agent_prompts.py and agent/tool modules.
  • Tools: Function tools mirror agent versions when their prompts or behavior change (odd_agents/tools/).
  • Knowledge & ODD docs: Core knowledge, robot profiles, and overlays tracked via revision/date in each doc header.
  • Data: Processed datasets are versioned in data/DATA_VERSIONS.md (production/test, processing params).
  • Reports & runs: Reports include pipeline/agent versions and the scenario/data version (see report metadata and archived results).

Naming & Bumping

  • Agents/Tools: vMAJOR.MINOR.PATCH (e.g., PerceptionAgent v7.4.0). Minor = behavior/prompt changes; Patch = small wording/stability tweaks.
  • Knowledge: Update revision/date in the doc header; summarize what changed and why.
  • Data: Follow {source}_{id}_v{n} and log params in data/DATA_VERSIONS.md.
  • Reports: Ensure generated artifacts stamp pipeline/agent/data versions.

Where Versions Surface

  • UI: Badges on the homepage and architecture page.
  • Artifacts: full_result.json, executive_summary.json, and HTML reports carry pipeline/agent/data versions.
  • Docs: This guide (overview), data/DATA_VERSIONS.md (data), knowledge doc headers (knowledge revisions).

How to Update

  1. Change code/prompt/knowledge/data.
  2. Bump the relevant version (agent/tool prompt file, knowledge header, or data manifest).
  3. Log the change (HISTORY/RESULTS where relevant; data changes in data/DATA_VERSIONS.md).
  4. Rerun workflows so reports pick up the new versions.
Quick checklist:
  • Agent or tool prompt changed → bump agent/tool version.
  • Knowledge doc edited → update its revision/date.
  • Data regenerated → add entry to data/DATA_VERSIONS.md.
  • Reports shipping → confirm pipeline/agent/data versions appear in metadata.
